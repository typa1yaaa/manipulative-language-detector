# manipulative-language-detector

Проект производственной практики: Обнаружение манипулятивных языковых паттернов в мошеннических сообщениях

------

## Описание проекта

Проект предназначен для обнаружения манипулятивных языковых паттернов в сообщениях, связанных с мошенничеством, пропагандой и другими формами речевого воздействия.

Основная задача — определить, содержит ли текст манипулятивные приемы, а также выделить соответствующие фрагменты текста и присвоить им типы.

## Формат работы модели

Модель решает задачу token-level multi-label classification: для каждого токена текста модель определяет наличие одного или нескольких типов манипулятивных приемов.

Поддерживаются, в частности, следующие типы:
- `emotional_triggering_language`
- `fear_uncertainty_pressure`
- `gain_loss_exaggeration`
- `cognitive_closure_cliches`
- `social_proof_pressure`
- `causal_fact_distortion`
- `doubt_uncertainty_injection`
- `topic_shift_misrepresentation`
- `directive_action_pressure`

## Структура проекта

- `data/` — директория с данными (корпус `ru_token_cls_dataset`).
- `notebooks/` — ноутбуки для исследования, подготовки данных и обучения модели.
- `src/` — исходный код основных функций модели.
- `service/` — веб-сервис (`backend` и `frontend`).
- `tests/` — автоматические тесты.
- `.github/workflows/` — конфигурация CI (GitHub Actions).
- `docker-compose.yml` — конфигурация для контейнеризации.

Обученная модель опубликована на [Hugging Face: `ksruasdh/manipulation-detector-ru`](https://huggingface.co/ksruasdh/manipulation-detector-ru).

> Модель не требуется скачивать вручную. При первом запуске Docker Compose отдельный сервис `model-downloader` автоматически загружает модель с Hugging Face в общий Docker volume. После успешного скачивания запускается backend, который использует модель из этого volume.

## Запуск сервиса

Проект упакован в Docker и состоит из трех сервисов:

- `model-downloader` — автоматически загружает обученную модель с Hugging Face;
- `backend` — REST API для анализа текста;
- `frontend` — пользовательский интерфейс на Streamlit.

### Требования

- Docker
- Docker Compose v2

### Команда запуска

Для сборки и запуска выполните в корне проекта:

```bash
docker compose up --build
```

> При первом запуске загрузка модели может занять несколько минут, поскольку размер модели составляет около 700 МБ. Последующие запуски используют сохраненную модель из Docker volume и не требуют повторной загрузки.

После старта доступны:

- **Backend API:** [http://localhost:8000](http://localhost:8000)
- **Swagger-документация:** [http://localhost:8000/docs](http://localhost:8000/docs)
- **Пользовательский интерфейс:** [http://localhost:8501](http://localhost:8501)

## Этапы разработки проекта

Проект состоит из трех этапов:

### 1. Подготовка данных
В ноутбуке `notebooks/prepare_ru_manipulation_token_cls.ipynb`:
- загружается англоязычный корпус;
- выполняется перевод и фильтрация;
- загружается и обрабатывается русский корпус;
- унифицируются метки манипулятивных техник;
- сохраняется итоговый датасет для обучения.

### 2. Обучение и использование модели
В ноутбуке `notebooks/model-train.ipynb`:
- загружается подготовленный датасет;
- выполняется разбиение на обучающую и тестовую выборки;
- обучается модель token classification;
- сохраняется обученная модель в папку `models/manipulation_detector_model`;
- выполняется тестирование модели на примерах.

### 3. Сервис и тестирование
- Реализован веб-сервис, состоящий из REST API (backend) и пользовательского интерфейса (frontend).
- Написаны модульные тесты на основные компоненты системы (подготовка данных, лоссы, метрики, предиктор).


> Подробнее о работе проекта можно прочитать в отчете `reports.docx`.
